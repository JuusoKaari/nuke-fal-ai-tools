# v1.1.0 release-candidate prep

Short process spec for preparing the `work` branch as a v1.1.0 release candidate. Not an install guide.

## Goal

Leave `work` clean, tested, and reviewable for a later `work` -> `main` PR. The upcoming public version is **v1.1.0** (not v1.0.3).

## Do not do in this prep

- Do not merge into `main`.
- Do not create or push a git tag.
- Do not publish a GitHub Release.
- Do not force-push or rewrite history.
- Do not retitle CHANGELOG `[Unreleased]` to `[1.1.0]`. That happens only immediately before the real tag.

## Public vs private

`nuke-fal-ai-tools` is the public plugin. Everything committed here must be suitable for public release. Private planning, unattended runners, local workflow files, and secrets belong in the sibling `nuke-fal-ai-tools_devtools` repo (already split). Product and source changes belong here.

## Release ZIP

The GitHub Release asset is an end-user install, not a development checkout. Prefer an explicit allowlist of installable paths over a growing exclusion list, unless an allowlist would risk omitting runtime files under `nuke/`.

Must ship: `init.py`, `menu.py`, `nuke/groups/`, `nuke/python/`, `requirements-python3.txt`, `README.md`, `LICENSE`, user docs (`docs/INSTALL.md`, `docs/troubleshooting.md`), and `tools/print_install_line.py` (documented in INSTALL).

Must not ship: `.git`, `.github`, tests, planning, `dev_tools`, `unattended-todo.json`, `__pycache__`, bytecode, `dist`, and other development-only artifacts.

A `v*` tag must run the same unit-test suite as CI, then validate the ZIP, before publishing. Failed tests or a bad ZIP must stop the job.

## Docs

Keep `[Unreleased]` as the heading. Polish those notes so they can become the v1.1.0 changelog later. README should not say v1.0.2 is current. Derive the tool count and category table from `nuke/python/_fal_tools.py` (`_TOOLS`), do not guess. Helpers need **system Python 3.9+**, distinct from Nuke's embedded Python. Do not imply users replace Nuke's Python.

## Stop

After prep: tests green, tree clean of temp/release artifacts, branch ready for a human `work` -> `main` PR. Tagging and GitHub Release stay manual.
